# Prova no box (0.7.0)

O bot rodou os testes no box em 06/11/2026, com o grokbot-kit 0.7.0 instalado do PyPI. Responder um pedido de
permissão durante a tarefa funcionou de ponta a ponta no Claude Code e no opencode 2.2.5. Os JSONs completos dos
eventos estão nos relatórios do bot. Aqui ficam só os campos que provam o comportamento.

## Atualização

```text
grokbot-kit 0.6.0 -> 0.7.0
APPLY_EXIT=0
grokbot-kit 0.7.0
```

O `setup cli upgrade opencode` não passou o opencode da 1.x para a 2.x (#49). O instalador oficial ficou na 1.19.5
(`opencode 1.19.5 is already the latest`). O bot subiu para a 2.x com `opencode upgrade --major`, que levou à
`opencode v2.2.5`. Depois rodou `grokbot-kit install opencode`, e o plugin ficou com a primeira linha
`// grokbot-kit opencode plugin for opencode 2`.

Depois da troca de major, o login do opencode-go sumiu e o `opencode auth list` voltou vazio. O bot fez o login de
novo pelo OpenCode Console (device code, com `--standalone`, porque o serviço em segundo plano falhou com
`Integration not found: opencode`) e rodou `opencode service restart`. Só então o `setup models refresh opencode`
listou os 32 modelos `opencode-go/`. Os tiers do opencode foram regravados só com ids `opencode-go/`.

## opencode 2.2.5: pedido de rede, respondido pelo usuário

Na primeira rodada não chegou nenhum `needs_input`. Sem `permission` no config, o opencode 2 libera o shell, então o
`curl` rodou direto e a tarefa terminou `completed/ok` (`20261106T152644-prova-reply-opencode-9978f3`). Na segunda
rodada, o diretório do teste tinha um `opencode.json` com `{"permission": {"bash": "ask"}}`.

A tarefa foi `20261106T191201-prova-reply-opencode-f72ad4`, com o tier `trivial` e o modelo
`opencode-go/glm-5.3-flash`.

```text
needs_input  19:12:04Z  tool_name=shell  detail="curl -sI https://example.com, head -1"
             request_id=chatcmpl-tool-825b3a3f3881a449  reply_deadline=2026-11-06T19:22:05Z
             entregue à routine: http_status=200
reply        recorded allow for chatcmpl-tool-825b3a3f3881a449 (by user)  exit=0
completed    19:25:19Z  status=ok  exit_reason=success  exit_code=0  summary: "HTTP/2 200"
```

O `meta.json` tem `ask_wait_seconds` = `600`. O `kit.log`:

```text
2026-11-06T19:12:01Z launch opencode model=opencode-go/glm-5.3-flash timeout=1800s
2026-11-06T19:20:14Z reply: allow for chatcmpl-tool-825b3a3f3881a449 by user
2026-11-06T19:25:19Z exit 0: completed/ok/success
```

Ficou uma pergunta aberta. Entre o `allow` (19:20:14) e o fim (19:25:19) passaram cerca de 5 minutos, enquanto no
Claude Code foram 2 segundos. O `emit` lê a resposta a cada `POLL_SECONDS`, e o `allow` chegou antes do prazo
(19:22:05), então a espera não explica a diferença. Falta a linha do tempo do `out.jsonl` para saber se o tempo foi
do modelo, do `curl` ou do opencode.
